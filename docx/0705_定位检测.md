## 一、本周工作总结

### 1. 持续定位监控方案探索

**需求**：导航过程中检测定位是否出错。

**尝试过的方案**：

| 方案 | 结果 |
|------|------|
| RTAB-Map 内置 `loc_thr` 诊断 | ❌ 初始化时序 bug，`getMemory()` 为 null，诊断任务注册失败 |
| 直接读 `/diagnostics` | ❌ 因为 `loc_thr` 诊断没注册，输出为空 |
| 订阅 `/localization_pose` 看协方差 | ⚠️ 仅反映 RTAB-Map 自身置信度，不代表真实准确性 |
| 监控 `loop_closure_id` | ❌ 纯 ICP 模式下永远为 0（这是正常的） |
| **监控 odom_cache 近邻链接 + 协方差 + 位姿突变** | ✅ 最终方案 |

### 2. 关键发现：`loop_closure_id` 在纯 ICP 模式下永远为 0

**原因**：

- `loop_closure_id` 是 RTAB-Map **视觉回环检测**（Bag-of-Words）流水线的产物
- 当 `Reg/Strategy=1`（ICP）且 `Kp/MaxFeatures=-1`（无视觉特征）时，视觉回环检测路径不走
- **这是正常的，不是定位失败**

**实际的定位机制**：

- RTAB-Map 在定位模式下加载数据库节点到 working memory
- 每帧通过 ICP 匹配当前扫描与数据库节点
- 匹配结果存储在 `odom_cache` 的 type=2 链接中（proximity link）
- 这些链接的存在说明 ICP 匹配正常工作

## 二、最终定位检测方案

### 架构

```
/localization_pose ──→ ┌─────────────────────┐
                       │ localization_monitor │──→ 日志输出
/info ──────────────→  └─────────────────────┘
```

监控节点同时订阅两个话题，综合判断。

### 四个检测维度

#### 1. 协方差突增 `[COV]`

- **数据源**：`/localization_pose` 的 `covariance[0]`（x 方差）和 `covariance[7]`（y 方差）
- **判断**：`max(σ_x, σ_y) > threshold`（默认 2.0m）
- **含义**：RTAB-Map 对定位结果不确定，可能 ICP 匹配质量差
- **局限**：RTAB-Map 可能"自信地错"——协方差小但位置已经错了

#### 2. 位姿突变 `[JUMP]`

- **数据源**：相邻两帧 `/localization_pose` 的位置差
- **判断**：`sqrt(dx² + dy²) > jump_threshold`（默认 0.5m）
- **含义**：一帧内位置跳变过大，可能是 ICP 匹配到了错误位置
- **注意**：正常导航中偶尔会有小跳变（过门槛、地面不平）

#### 3. 近邻链接丢失 `[LOST]`

- **数据源**：`/info` 的 `odom_cache.links` 中 type=2 的数量
- **判断**：prox_links 从 >0 变为 0
- **含义**：ICP 不再匹配到任何数据库节点，定位完全丢失
- **恢复**：prox_links 重新 >0 时输出 `[RECOVER]`

#### 4. 离数据库节点过远 `[DRIFT]`

- **数据源**：`/info` 的 `stats_values` 中 `Memory/Closest_node_distance/m`
- **判断**：最近数据库节点距离 > max_closest（默认 5.0m）
- **含义**：机器人可能跑出了建图范围，没有可参考的地图数据

### 周期状态输出

每 10 秒输出一次：

```
[STATUS] pos=(0.48,0.46) prox_links=20 frames=17
```

| 字段 | 含义 |
|------|------|
| `pos` | 当前估计位置 |
| `prox_links` | odom_cache 中的近邻链接数（>0 说明 ICP 在工作） |
| `frames` | 已处理的总帧数 |

### 使用方法

```bash
# 默认参数启动
python3 scripts/localization_monitor.py

# 自定义阈值
python3 scripts/localization_monitor.py --threshold 2.0 --jump-threshold 0.5 --max-closest 5.0

# 后台运行
python3 scripts/localization_monitor.py &
```

### 阈值调参建议

| 参数 | 默认值 | 建议范围 | 说明 |
|------|--------|----------|------|
| `--threshold` | 2.0m | 0.5 ~ 3.0 | 协方差标准差阈值，越小越敏感 |
| `--jump-threshold` | 0.5m | 0.2 ~ 1.0 | 单帧位移阈值，越小越敏感 |
| `--max-closest` | 5.0m | 2.0 ~ 10.0 | 离数据库节点最远距离 |

## 三、已知局限

1. **无法检测"自信地错"**：如果 RTAB-Map 匹配到了错误的数据库节点但 ICP 收敛良好，协方差会很小，近邻链接也存在。这种情况需要外部验证（如 GPS、路标）。

2. **近邻链接数量不等于匹配质量**：prox_links 只说明有链接，不代表位置正确。需要结合信息矩阵（information matrix）判断匹配质量，但目前未实现。

3. **纯 ICP 模式无回环检测**：没有视觉词典，RTAB-Map 无法通过 Bag-of-Words 发现回环。长时间导航会累积漂移，只能靠 ICP 近邻匹配修正。

4. **数据库覆盖范围有限**：机器人跑出建图范围后，没有可参考的节点，定位会失效。
