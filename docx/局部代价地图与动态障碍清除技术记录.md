# 局部代价地图与动态障碍清除技术记录

## 1. 背景

在导航过程中，行人从机器人前方经过后，局部代价地图中有时会留下条状障碍残影。该残影会影响 Nav2 局部规划和控制，使机器人减速、绕行或短暂停滞。

本记录整理 `xz/rtabmap_nav2_stack` 项目中局部代价地图的产生方式、高度过滤含义、动态障碍残留原因，以及本次针对 clearing 射线覆盖效率的参数调整。

## 2. 系统数据流

项目导航链路分工如下：

```text
Livox 雷达 + IMU
    -> FAST-LIO
    -> /cloud_registered_body
    -> Nav2 local_costmap / VoxelLayer
    -> InflationLayer
    -> /local_costmap/costmap
```

其中：

- `FAST-LIO` 负责雷达惯性里程计，发布去畸变后的点云 `/cloud_registered_body`。
- `RTAB-Map` 主要负责全局建图、回环、重定位和 `map -> odom`。
- `Nav2` 负责规划、控制和避障。
- 局部代价地图不是 RTAB-Map 直接发布的地图，而是 Nav2 根据实时点云在 `odom` 坐标系下滚动生成的。

FAST-LIO 发布 `/cloud_registered_body` 时，点云 frame 为 `base_footprint`：

```cpp
laserCloudmsg.header.frame_id = "base_footprint";
pubLaserCloudFull_body->publish(laserCloudmsg);
```

对应源码：

```text
src/FAST_LIO_ROS2/src/laserMapping.cpp
```

## 3. 局部代价地图配置

局部代价地图配置文件：

```text
src/robot_bringup/config/nav2_common.yaml
```

核心参数：

```yaml
local_costmap:
  local_costmap:
    ros__parameters:
      update_frequency: 10.0
      publish_frequency: 5.0
      global_frame: odom
      robot_base_frame: base_footprint
      rolling_window: true
      width: 8
      height: 8
      resolution: 0.05
      robot_radius: 0.22
      plugins: ['voxel_layer', 'inflation_layer']
```

含义：

- `global_frame: odom`：局部代价地图运行在里程计坐标系下。
- `robot_base_frame: base_footprint`：机器人底盘坐标系。
- `rolling_window: true`：局部地图跟随机器人移动。
- `width: 8`, `height: 8`：局部地图大小为 8m x 8m。
- `resolution: 0.05`：栅格分辨率为 5cm。
- `voxel_layer`：使用 3D 点云生成障碍物。
- `inflation_layer`：对障碍物进行膨胀，给机器人留安全距离。

## 4. 高度过滤的含义

高度过滤指只处理指定 `z` 高度范围内的点云。由于 `/cloud_registered_body` 的 frame 是 `base_footprint`，这里的高度通常可理解为相对机器人底盘坐标系的 `z` 值。

原始配置中：

```yaml
min_obstacle_height: 0.01
max_obstacle_height: 1.00
```

含义：

- `z < 0.01m`：忽略，通常是地面点、地面噪声或低矮杂点。
- `0.01m <= z <= 1.00m`：作为有效障碍物点参与代价地图更新。
- `z > 1.00m`：忽略，通常是高处结构或机器人不会撞到的物体。

高度过滤的目的：

- 避免地面点被标记成障碍物。
- 忽略机器人底盘不会碰撞到的高处物体。

注意：同一个 observation source 同时用于 marking 和 clearing 时，高度过滤也会影响 clearing。被过滤掉的低处地面点不能参与清除射线计算。

## 5. marking 与 clearing

Nav2 的点云障碍层有两类行为：

```yaml
marking: true
clearing: true
```

### 5.1 marking

`marking` 表示把点云命中的位置标记为障碍物。

人在雷达前走动时，点云打到人的身体或腿部，对应栅格会被标记为障碍物。

### 5.2 clearing

`clearing` 表示使用当前点云从传感器原点向点云点位做 raytrace，清除射线路径上的自由空间。

人走开后，旧障碍不会简单按固定秒数自动消失，而是需要后续点云的 clearing 射线穿过旧障碍格子，将其清掉。

VoxelLayer 的更新逻辑可以概括为：

```text
1. 获取 marking observations
2. 获取 clearing observations
3. 先执行 raytraceFreespace 清除自由空间
4. 再把当前点云命中的点标记为障碍
```

因此条状残影的本质通常是：

```text
旧障碍已经被标记，但后续 clearing 射线没有充分穿过这些旧障碍格子。
```

## 6. observation_persistence 的作用

Nav2 中存在参数：

```yaml
observation_persistence
```

该参数控制观测缓存时间。源码中默认值为 `0.0`。

`observation_persistence: 0.0` 的含义不是“障碍物 0 秒后自动消失”，而是 observation buffer 只保留最新一帧观测。

也就是说，在当前项目没有额外配置 `observation_persistence` 的情况下，动态障碍残留主要不是历史点云缓存过久导致的，而是 costmap 中已经被标记的障碍没有被 clearing 射线及时擦除。

## 7. 条状障碍残留的常见原因

### 7.1 清除距离小于标记距离

原始配置：

```yaml
raytrace_max_range: 3.5
obstacle_max_range: 4.0
```

含义：

- 最远 4.0m 的点可以被标记为障碍。
- 但 clearing 射线最多只清到 3.5m。

这会产生一个风险区域：

```text
3.5m ~ 4.0m 范围内：能标记，但清除能力不足。
```

人在该范围走动时，容易留下残影。

### 7.2 高度过滤导致地面点无法参与清除

人走开后，雷达可能重新打到地面。如果地面点高度低于 `min_obstacle_height`，这些点会被过滤掉，无法参与 clearing。

结果是：旧障碍所在区域虽然已经空了，但没有足够射线穿过旧障碍栅格。

### 7.3 Livox 点云覆盖不均匀

Livox/MID360 点云不是传统 2D 激光那种固定平面扫描。动态物体走动时会形成一串点云命中，之后某些栅格不一定马上被新射线覆盖，因此更容易出现条状残影。

### 7.4 局部地图分辨率较细

当前 `resolution: 0.05`，即 5cm 一个格子。分辨率越细，对点云射线覆盖密度要求越高，稀疏点云更容易留下细碎残影。

## 8. 本次调整方案

本次只调整局部代价地图 `voxel_layer` 的 observation source，不改变地图大小、分辨率、膨胀半径和控制器参数。

调整前：

```yaml
observation_sources: lidar_cloud
lidar_cloud:
  topic: /cloud_registered_body
  data_type: PointCloud2
  clearing: true
  marking: true
  min_obstacle_height: 0.01
  max_obstacle_height: 1.00
  raytrace_min_range: 0.0
  raytrace_max_range: 3.5
  obstacle_min_range: 0.0
  obstacle_max_range: 4.0
```

调整后：

```yaml
observation_sources: mark_cloud clear_cloud

mark_cloud:
  topic: /cloud_registered_body
  data_type: PointCloud2
  marking: true
  clearing: false
  min_obstacle_height: 0.05
  max_obstacle_height: 1.00
  raytrace_min_range: 0.0
  raytrace_max_range: 4.2
  obstacle_min_range: 0.0
  obstacle_max_range: 4.0

clear_cloud:
  topic: /cloud_registered_body
  data_type: PointCloud2
  marking: false
  clearing: true
  min_obstacle_height: -0.20
  max_obstacle_height: 1.20
  raytrace_min_range: 0.0
  raytrace_max_range: 4.5
  obstacle_min_range: 0.0
  obstacle_max_range: 4.0
```

### 8.1 mark_cloud

`mark_cloud` 只负责标记障碍物：

- `marking: true`
- `clearing: false`
- `min_obstacle_height: 0.05`
- `max_obstacle_height: 1.00`

作用：

- 更严格地过滤地面噪声。
- 避免低矮地面点被标成障碍。
- 保持障碍物最大标记范围为 4.0m。

### 8.2 clear_cloud

`clear_cloud` 只负责清除障碍物：

- `marking: false`
- `clearing: true`
- `min_obstacle_height: -0.20`
- `max_obstacle_height: 1.20`
- `raytrace_max_range: 4.5`

作用：

- 允许地面点、低处点参与 clearing。
- 清除射线范围大于障碍标记范围。
- 提高旧障碍被射线穿过并清除的概率。

## 9. 调整影响分析

### 9.1 正面影响

- 行人走开后的条状残影应更快消失。
- 3.5m ~ 4.0m 区域不再处于“能标记但清不到”的状态。
- 地面点可用于 clearing，但不会被 marking source 标成障碍。

### 9.2 可能副作用

- clearing 更积极，点云稀疏或短暂漏扫时，部分边缘障碍可能出现轻微闪烁。
- raytrace 距离从 3.5m 增加到 4.5m，CPU 计算量略增。
- 对玻璃、黑色低反射物体、细杆等难检测目标，过强 clearing 可能更容易清掉旧障碍，需要现场验证。

### 9.3 不会改变的内容

- 不改变局部地图大小，仍为 8m x 8m。
- 不改变局部地图分辨率，仍为 0.05m。
- 不改变障碍标记最大距离，仍为 4.0m。
- 不改变膨胀半径，仍为 `inflation_radius: 0.45`。
- 不影响全局地图 `/map`。

## 10. 验证方法

### 10.1 重启导航

修改参数后需要重启 Nav2 才会生效。

### 10.2 检查点云频率

```bash
ros2 topic hz /cloud_registered_body
```

关注点云频率是否稳定。点云频率过低会影响 clearing 效率。

### 10.3 检查点云数据

```bash
ros2 topic echo /cloud_registered_body --once
```

关注：

- `header.frame_id` 是否为 `base_footprint`
- `width` 是否过小
- 点云是否持续更新

### 10.4 RViz 观察

重点显示：

```text
/local_costmap/costmap
/cloud_registered_body
```

测试流程：

1. 启动导航。
2. 让人从机器人前方 2m ~ 4m 范围横向走过。
3. 观察局部代价地图中是否出现条状障碍。
4. 人离开后观察残影消失速度。
5. 对比调整前是否明显改善。

## 11. 后续可选调参方向

如果残影仍明显，可继续按以下顺序排查：

### 11.1 提高局部代价地图更新频率

当前：

```yaml
update_frequency: 10.0
publish_frequency: 5.0
```

可尝试：

```yaml
update_frequency: 15.0
publish_frequency: 8.0
```

注意 CPU 占用会增加。

### 11.2 缩短障碍标记范围

如果远处行人干扰较大，可尝试：

```yaml
obstacle_max_range: 3.5
raytrace_max_range: 4.0
```

代价是机器人对远处障碍的提前避障能力下降。

### 11.3 调整地图分辨率

当前：

```yaml
resolution: 0.05
```

如果点云稀疏导致细碎残影较多，可尝试：

```yaml
resolution: 0.07
```

或：

```yaml
resolution: 0.10
```

代价是障碍边界和局部规划会更粗糙。

### 11.4 检查 FAST-LIO 点云稠密度

如果 `/cloud_registered_body` 点数太少，clearing 射线天然不足。需要检查 FAST-LIO 的降采样、发布频率和雷达驱动状态。

## 12. 结论

动态行人导致局部代价地图出现条状残影，核心原因通常不是障碍物有固定“残留时间”，而是旧障碍被标记后，没有被后续 clearing 射线及时穿过并清除。

本次调整通过拆分 `mark_cloud` 与 `clear_cloud`，让障碍标记更严格、自由空间清除更充分：

- marking 过滤低处地面噪声。
- clearing 允许地面点参与清除。
- clearing 射线范围大于障碍标记范围。

预期效果是提高动态障碍离开后的清除效率，减少导航过程中由行人走动造成的条状障碍残影。
