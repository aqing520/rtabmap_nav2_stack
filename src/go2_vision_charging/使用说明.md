# GO2机器人视觉自动充电系统 - 使用说明

## 一、系统简介

基于 AprilTag（[apriltag_ros](https://github.com/AprilRobotics/apriltag_ros)）的四足机器人自动充电系统,实现厘米级精准对接。

**核心功能**:
- AprilTag 视觉识别与定位（物理标签须为 tag36h11，与旧版 ArUco 码不兼容）
- 实时位姿滤波与坐标转换
- PID视觉伺服控制
- 自动充电状态机

**性能指标**:
- 对接精度: 前后±1.8cm, 左右±1.2cm, 角度±2.3°
- 收敛时间: 3.1秒 (标准场景)
- 成功率: 95%
- 工作距离: 0.3-3.0米

---

## 二、系统要求

### 硬件要求
- 宇树GO2四足机器人
- 头部相机(1920×1080, 30fps)
- AprilTag 标签（族 `tag36h11`，ID=88；打印外轮廓需按实际测量，使 [apriltag 定义的 tag边长](https://github.com/AprilRobotics/apriltag/wiki/AprilTag-User-Guide#pose-estimation) 与 `config/apriltag_tags.yaml` 中 `size: 0.184` 一致，约 18.4cm 量级）

### 软件环境
- Ubuntu 20.04 / ROS Noetic
- Python 3.8+
- OpenCV 4.x
- 依赖包: `apriltag_ros`（及底层 [apriltag](https://github.com/AprilRobotics/apriltag) 库）, `video_stream_opencv`, `tf2_ros`, `tf2-geometry-msgs`, `rqt-image-view`

## 三、系统架构与依赖

### 系统分层结构

```
┌──────────────────────────────────────────┐
│  ROS2底层运控系统 (ws_ros2)              │
│  - 机器人底层控制                         │
│  - /cmd_vel 话题接收                      │
│  - inspecting_state 控制导航开关          │
└──────────────────────────────────────────┘
                   ↑
        /cmd_vel, /inspecting_state
                   │
┌──────────────────────────────────────────┐
│  ROS1导航与建图系统 (ws_nav)              │
│  - Fast-LIO SLAM (3D激光SLAM)            │
│  - 导航规划器 (pure_pursuit)              │
│  - 键盘控制 (可选)                        │
└──────────────────────────────────────────┘
                   ↑
              TF, map frame
                   │
┌──────────────────────────────────────────┐
│  视觉充电系统 (go2_vision_charging)       │
│  - AprilTag 视觉检测（apriltag_ros）       │
│  - 充电对接控制                           │
└──────────────────────────────────────────┘
```

### 关键依赖关系

1. **TF坐标系**: 视觉充电依赖SLAM系统提供的`map -> odom -> laser_link -> base_link`变换
2. **cmd_vel仲裁**: 充电时需禁用导航系统，避免速度指令冲突
3. **底层运控**: ROS2系统接收并执行最终速度指令

### 4. 远程 `robot_runner` 容器：同步代码与编译（示例）

部分现场设备通过 **SSH 登录宿主机**，ROS Noetic 工作空间在 **`robot_runner` Docker 容器内**（路径通常为 `/root/ws_nav`）。可在开发机上改完 `go2_vision_charging` 后，按下列方式同步进容器并编译。

**1）登录宿主机并进入容器**

```bash
# 示例：自定义 SSH 端口时加 -p（以现场为准）
ssh -p 7300 wheeltec@smartai.com

docker exec -it robot_runner bash
source /opt/ros/noetic/setup.bash
```

**2）在开发机推送代码到宿主机，再拷进容器**

在开发机执行（将 `YOUR_LOCAL_GO2_VISION_CHARGING` 换成本地功能包目录）：

```bash
REMOTE_USER_HOST="wheeltec@smartai.com"
REMOTE_SYNC_DIR="~/go2_vision_charging_sync"
CONTAINER_PKG="/root/ws_nav/src/go2_real/go2_vision_charging"

rsync -avz --delete -e "ssh -p 7300" \
  YOUR_LOCAL_GO2_VISION_CHARGING/ \
  "${REMOTE_USER_HOST}:${REMOTE_SYNC_DIR}/"

ssh -p 7300 "${REMOTE_USER_HOST}" \
  "docker cp ${REMOTE_SYNC_DIR}/. robot_runner:${CONTAINER_PKG}/"
```

**3）容器内安装依赖并编译**

```bash
# 已在容器 shell 中
apt-get update
apt-get install -y ros-noetic-apriltag-ros ros-noetic-video-stream-opencv \
  ros-noetic-cv-bridge ros-noetic-tf2-ros ros-noetic-tf2-geometry-msgs \
  ros-noetic-camera-calibration

cd /root/ws_nav
source /opt/ros/noetic/setup.bash
```

若工作空间曾配置 **`CATKIN_WHITELIST_PACKAGES`**（仅编译白名单包），直接 `catkin_make` 可能不会编到 `go2_vision_charging`。可**仅编本包**验证：

```bash
catkin_make -DCATKIN_WHITELIST_PACKAGES="go2_vision_charging" --pkg go2_vision_charging
source /root/ws_nav/devel/setup.bash
rospack find go2_vision_charging
```

需要恢复**整工作空间**编译时，先清空白名单再编（以现场 CMake 缓存为准，必要时删除 `build/devel` 后重配）：

```bash
cd /root/ws_nav
catkin_make -DCATKIN_WHITELIST_PACKAGES=""
# 或按原项目文档恢复原有白名单后再 catkin_make
```

## 五、充电座准备

### 1. AprilTag 标签制作

**规格要求**（须与 [`config/apriltag_settings.yaml`](config/apriltag_settings.yaml)、[`config/apriltag_tags.yaml`](config/apriltag_tags.yaml) 一致）:
- 族: `tag36h11`（见 `apriltag_settings.yaml` 中 `tag_family`）
- 标签 ID: `88`
- `size` 字段: `0.184`（米），含义为 **黑白交界边长**，非最外框；详见 [AprilTag User Guide — pose estimation](https://github.com/AprilRobotics/apriltag/wiki/AprilTag-User-Guide#pose-estimation)
- 打印要求: 高精度打印,避免失真

**生成方法**:
- 使用官方资源生成 **tag36h11**、ID **88** 的图像: [AprilTag 项目主页](https://april.eecs.umich.edu/software/apriltag.html) 或 [apriltag_ros Wiki](http://wiki.ros.org/apriltag_ros)
- 勿再使用 OpenCV `cv2.aruco` 生成图样：与 AprilTag **不兼容**，检测器无法识别

**打印指南**:
1. 使用高质量打印机(推荐激光打印机)
2. 白纸黑墨,对比度要高
3. 打印后按 AprilTag 文档测量 **tag size**（黑白交界边长），与 `apriltag_tags.yaml` 中数值一致；若对接距离系统偏差，优先修正该尺寸而非盲目改 PID
4. 打印后用尺子验证尺寸精度(±1mm)

### 2. 二维码安装位置

**关键原则**: 
- 二维码应安装在充电座**上方或后方**固定位置
- 二维码平面与地面保持**垂直**
- 充电插口应在二维码**下方**

**测量几何偏移** (参考下图):
```
            ┌─────────────┐
            │  AprilTag   │ ← 标签中心 (参考点)
            │   ID: 88    │
            └─────────────┘
                  │
                  │ offset_y (垂直偏移, 负值)
                  ↓
            ┌─────────────┐
            │  充电插口   │ ← 充电目标点
            └─────────────┘
                  │
                  │ offset_z (深度偏移, 负值)
                  ↓
            ══════════════════ 充电座底面
```

**测量步骤**:
1. 确定二维码中心点为原点(0, 0, 0)
2. 测量充电插口中心相对原点的位置:
   - `offset_x`: 左右偏移 (正=右侧, 负=左侧, 通常为0)
   - `offset_y`: 上下偏移 (正=上方, 负=下方, 通常为负值)
   - `offset_z`: 前后偏移 (正=前方, 负=后方, 通常为负值)
3. 在`config/charging_params.yaml`中填入测量值

### 3. 安装验证

```bash
# 启动相机与 AprilTag 检测
roslaunch go2_vision_charging auto_charge_demo.launch

# 手持充电座,将标签对准相机
rostopic echo /aruco_poses
# 可选：原始检测数组、桥接前 PoseStamped
# rostopic echo /tag_detections
# rostopic echo /aruco_pose_raw

# 检查检测稳定性:
# - 位置(xyz)波动应<2cm
# - 姿态角波动应<5°
# - 检测率应>90% (不应频繁丢失)
```

## 六、参数配置

### 1. 相机标定 (config/camera_info.yaml)

如果使用不同相机,需重新标定。当前配置:
- 分辨率: 1920×1080
- 焦距: fx=1818.13, fy=1808.25
- 光心: cx=1025.80, cy=510.61

**标定方法**:
```bash
# 使用ROS相机标定工具
rosrun camera_calibration cameracalibrator.py \
  --size 8x6 --square 0.03 \
  image:=/camera/image_raw camera:=/camera
```

### 2. 几何参数配置 (config/charging_params.yaml)

**必须根据实际测量修改以下参数**:

```yaml
geometry:
  offset_y: -0.616   # 充电口相对二维码上下偏移(米) ⚠️
  offset_z: -1.00    # 充电口相对二维码前后偏移(米) ⚠️
  offset_x: 0.0      # 充电口相对二维码左右偏移(米)
```

**测量方法**:
1. 将二维码贴在充电座上方/后方固定位置
2. 测量充电插口中心点相对二维码中心的三维偏移
3. 坐标系定义(相机坐标系):
   - X轴: 右侧为正
   - Y轴: 下方为正  
   - Z轴: 前方为正

### 3. 相机外参配置 (launch/auto_charge_demo.launch)

根据相机在机器人上的安装位置修改:

```xml
<!-- base_link -> camera_link 的静态TF -->
<!-- 参数: x y z yaw pitch roll (米, 弧度) -->
<node pkg="tf2_ros" type="static_transform_publisher" 
      args="0.1 0 0.616 -1.5707 0 -1.5707 base_link camera_link" />
      <!-- ↑     ↑   ↑      ↑       ↑     ↑
           前后 左右 上下   偏航角  俯仰角 翻滚角 -->
```

**测量方法**:
- xyz: 测量相机镜头中心相对机器人本体中心的位置
- 旋转角: 根据相机朝向确定(常见配置: -90°偏航 + -90°翻滚)


## 七、快速启动脚本 (推荐)

### 创建启动脚本

```bash
# 创建充电模式切换脚本
cat > ~/ws_nav/switch_to_charging_mode2.sh << 'EOF'
#!/bin/bash
echo "正在切换到充电模式..."

# 停止导航节点
echo "1. 停止导航系统..."
rosnode kill /pure_pursuit_local_planner 2>/dev/null
rosnode kill /keyboard_control_node 2>/dev/null
sleep 1

# 禁用导航速度（ROS2）
echo "2. 禁用导航速度指令..."
ros2 topic pub /inspecting_state std_msgs/msg/Bool '{data: false}' -r1 &
ROS2_PID=$!
sleep 2
kill $ROS2_PID

# 检查cmd_vel发布者
echo "3. 验证速度指令权限..."
PUBLISHERS=$(rostopic info /cmd_vel | grep Publishers -A 10)
echo "$PUBLISHERS"

if echo "$PUBLISHERS" | grep -q "charging_state_machine"; then
    echo "✓ 充电系统已获得控制权"
    echo "✓ 可以开始充电流程"
else
    echo "⚠ 警告: 充电系统未正确连接"
fi

echo "完成! 请将机器人移至充电座前方"
EOF

chmod +x ~/ws_nav/switch_to_charging_mode.sh
```

## 九、参数调优

### 1. PID参数调整 (charging_params.yaml)

**如果出现以下问题**:

| 问题 | 调整参数 | 方向 |
|------|---------|------|
| 对接速度太快/冲击大 | `max_v_x` | 减小到0.10 |
| 对接速度太慢 | `k_p_x`, `k_p_y` | 各增加0.1 |
| 接近时震荡 | `k_d_x`, `k_d_y` | 各增加0.05 |
| 稳态误差大 | `k_i_x`, `k_i_y` | 各增加0.01 |

**当前推荐配置**:
```yaml
pid:
  k_p_x: 0.5    # 前后P增益
  k_p_y: 0.8    # 左右P增益  
  k_p_z: 1.2    # 旋转P增益
  k_i_x: 0.05   # I增益
  k_i_y: 0.05
  k_i_z: 0.08
  k_d_x: 0.1    # D增益
  k_d_y: 0.1
  k_d_z: 0.15

limits:
  max_v_x: 0.15   # 最大前后速度(m/s)
  max_v_y: 0.10   # 最大左右速度(m/s)
  max_w_z: 0.4    # 最大角速度(rad/s)
```

### 2. 角度融合权重调整  （这个目前代码里没用使用，如果角度不准，可以尝试使用）

**如果大角度场景(>30°)下角度估计不准**:

```yaml
# 增大几何角权重
angle_fusion_weight: 0.8  # 默认0.7

# 范围: 0.0-1.0
# 0.0 = 完全使用二维码姿态角(适合小角度)
# 1.0 = 完全使用几何计算角度(适合大角度)
# 0.7 = 推荐平衡值
```

### 3. 容差调整

**如果对接后频繁进出DOCKED状态**:

```yaml
tolerance:
  dist: 0.05      # 距离容差放宽到0.06
  lateral: 0.03   # 横向容差放宽到0.04
  yaw: 0.08       # 角度容差放宽到0.10
```

## 十、常见问题

### Q1: 无法检测到二维码

**检查清单**:
```bash
# 1. 相机是否正常
rostopic hz /camera/image_raw  # 应有~30Hz输出
rosrun rqt_image_view rqt_image_view  # 查看图像质量

# 2. AprilTag 节点是否运行
rosnode list | grep apriltag

# 3. 标签是否在有效范围
rostopic echo /tag_detections      # AprilTagDetectionArray
rostopic echo /aruco_pose_raw      # 桥接后 PoseStamped（对准应有输出）
rostopic hz /aruco_poses
```

**可能原因**:
- 光照不足或过强 → 调整环境光
- 距离过近(<0.3m)或过远(>3m) → 调整位置
- 二维码污损/反光 → 清洁或重新打印
- 标签族/ID 与配置不一致 → 确认打印为 tag36h11、ID=88，且 `apriltag_tags.yaml` 已加载

### Q2: 速度指令冲突 (机器人不受充电系统控制)

**症状**: 充电状态机已启动,但机器人不移动或响应导航指令

**检查步骤**:
```bash
# 1. 查看cmd_vel的发布者
rostopic info /cmd_vel

# 应该只有充电系统发布:
# Publishers: 
#  * /charging_state_machine (geometry_msgs/Twist)

# 如果看到其他发布者(如pure_pursuit/keyboard_control):
# → 存在速度指令冲突
```

**解决方案**:
```bash
# 方法1: 停止其他控制节点
rosnode kill /pure_pursuit_local_planner
rosnode kill /keyboard_control_node

# 方法2: 使用ROS2禁用导航
ros2 topic pub /inspecting_state std_msgs/msg/Bool '{data: false}' -r1

# 方法3: 使用脚本
~/ws_nav/switch_to_charging_mode.sh
```

### Q3: TF变换错误

```bash
# 检查TF链路
rosrun tf tf_echo base_link camera_link
# 应输出变换矩阵,无报错

# 检查TF树结构
rosrun tf view_frames
evince frames.pdf  # 查看是否有断裂
```

**可能原因**:
- static_transform_publisher未启动 → 检查launch文件
- 相机外参配置错误 → 重新测量并修改
- 存在TF冲突(多个map→base_link) → 删除手动静态TF

### Q3: TF变换错误

```bash
# 检查TF链路
rosrun tf tf_echo base_link camera_link
# 应输出变换矩阵,无报错

# 检查TF树结构
rosrun tf view_frames
evince frames.pdf  # 查看是否有断裂

# ⚠️ 重要: 检查map→base_link变换
rosrun tf tf_echo map base_link
# 如果报错 "Frame [map] does not exist"
# → SLAM系统未启动或未正常运行
```

**可能原因**:
- SLAM系统(Fast-LIO)未启动 → 先启动建图系统
- static_transform_publisher未启动 → 检查launch文件
- 相机外参配置错误 → 重新测量并修改
- 存在TF冲突(多个map→base_link) → 删除手动静态TF

**解决方案**:
```bash
# 1. 确保SLAM正常运行
roslaunch fast_lio_slam mapping_mid360.launch

# 2. 验证TF链路完整性
rosrun tf tf_monitor
# 检查是否有断裂或延迟过大的链路

# 3. 重启充电系统
rosnode kill /charging_pose_transformer
roslaunch go2_vision_charging auto_charge_demo.launch
```

### Q4: 控制方向错误

**症状**: 机器人向左时应该向右,前进时后退等

**排查步骤**:
```bash
# 1. 检查充电目标坐标
rostopic echo /charging_goal_base
# pose.position.x应为前后距离(正=前方)
# pose.position.y应为左右偏移(正=左侧)

# 2. 检查base_link定义
rosrun tf tf_echo map base_link
# X轴应指向前方
```

**解决方案**:
- 检查launch文件中base_link→camera_link的TF参数
- 确认几何偏移参数符号正确

### Q5: 对接过程突然停止

```bash
# 查看当前状态
rostopic echo /charging_state

# 如果状态为RETREATING:
# → 二维码被遮挡,系统正在后退重试

# 如果状态为FAILED:
# → 超时或重试次数耗尽
```

**解决方案**:
- 降低速度限制避免过冲遮挡
- 增加超时时间:
  ```yaml
  timeout:
    align: 30.0  # 增加到45.0
  ```
- 检查相机视野是否足够

### Q6: 对接后频繁震荡

**原因**: PID参数不当或D项增益过小

**解决方案**:
1. 增大D增益抑制震荡:
   ```yaml
   k_d_x: 0.15  # 从0.1增加到0.15
   k_d_y: 0.15
   k_d_z: 0.20
   ```

2. 增加低通滤波系数:
   ```yaml
   filter:
     alpha: 0.2  # 从0.3减小到0.2
   ```

3. 放宽稳定判定容差:
   ```yaml
   tolerance:
     dist: 0.06
     lateral: 0.04
     yaw: 0.10
   ```

## 十五、未来优化方向

### 1. 基于ViSP IBVS的图像伺服控制

**当前方案**: 使用3D位姿(xyz + 姿态角) + PID控制  
**优化方案**: 使用ViSP库的IBVS (Image-Based Visual Servoing) 直接从像素坐标计算速度指令

**优势**:
- 无需3D位姿重建，减轻标签姿态估计误差
- 直接控制图像特征点位置，精度更高
- 对相机标定误差更鲁棒

**实现思路**:
```python
import visp_bridge
from visp.visual_features import vpFeaturePoint
from visp.vs import vpServo

# 1. 提取标签角点像素坐标（示例，需接当前检测器）
corners_current = tag_detector.get_corners()  # 4个角点

# 2. 定义期望特征位置(图像中心)
corners_desired = [[960, 540], [960, 540], ...]

# 3. 使用ViSP计算速度指令
servo = vpServo()
for i in range(4):
    s = vpFeaturePoint()
    s.buildFrom(corners_current[i][0], corners_current[i][1], Z)
    s_star = vpFeaturePoint()
    s_star.buildFrom(corners_desired[i][0], corners_desired[i][1], Z)
    servo.addFeature(s, s_star)

v = servo.computeControlLaw()  # 直接输出速度指令
```

**参考资源**:
- ViSP官方文档: https://visp-doc.inria.fr/
- ROS包: `ros-noetic-visp-bridge`

**适用场景**: 对精度要求极高(±5mm级别)或相机标定不准确的情况
